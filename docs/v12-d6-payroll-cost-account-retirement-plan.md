# D6 废弃 `6601 职工薪酬（成本）` · 方案

> ⛔ **实施前置条件（本方案成文后才发现，必须先解决）**
>
> 本方案的核心决定是「工资借方改挂 `660201` 管理费用-工资」。但 `660201` 在
> **`accounts` 表里叫「管理费用-办公费」**——库与 `chart-of-accounts.ts` 的管理费用
> 明细名称从迁移 049 起就整体错位，而 `chart-parity` 护栏明确豁免了名称比对，
> 一直没被发现。库里**根本没有「管理费用-工资」这个明细**。
>
> 照本方案实施的结果是：工资记进办公费，研发费用加计扣除的人工归集跟着错。
>
> 所以顺序是：**先修名称错位（含决定「管理费用-工资」明细的去留），再做 D6。**
> 完整证据见蓝图残留 11；同一处错位还让差旅费凭证记进了业务招待费（有多缴税的
> 后果）。本方案第二节「为什么是 660201 而不是 4001」的论证**不受影响**——那一段
> 讲的是「不能挂成本类」，与挂哪个管理费用明细是两件事。

> 状态：**待实施**（受上述前置条件阻塞）。由 D3（科目编码国标化）第九节「留给以后的」派生，
> 起因是 `6201 销售费用 → 6601` 的目标编码被这个科目占着，而它的设置本身存疑。
>
> 本方案的第一步是回答 D3 当时没有回答的问题：**`6601` 到底承载什么业务。**
> 结论是它不承载任何业务——所以废弃它，并顺手把 D3 剩下的那一项做完。

## 一、查清了什么：它承载的不是业务，是一个没做的决策

### 结论先行

`6601 职工薪酬（成本）` **不对应任何会计科目**。它是「工资计提的借方该挂哪里」
这个问题的**占位符**——把本该在记账时做出的费用归属判断，推迟成了一个总账级科目。

《企业会计准则》里职工薪酬的分录是：

```
借：生产成本 / 制造费用 / 管理费用 / 销售费用 / 研发支出   ← 按受益对象拆
贷：应付职工薪酬  2211
```

**贷方 FT 是对的**（`22110101` 应付职工薪酬-工资，2211 的叶子明细），
只有借方错。所以「拆解到 2211」这条路不存在：2211 侧一行都不用改。
错的是借方——它跳过了「这笔工资由谁受益」的判断。

### 证据一：真正的工资链路根本不用它

系统里有两套互相矛盾的工资计提做法：

| 入口 | 借方科目 | 代码 |
|---|---|---|
| 三险一金关账自动生成凭证 | `660201` 管理费用-工资 | `payroll/social-security-vouchers.ts:40` |
| 前端工资操作指引（给用户看的示范分录） | 管理费用-工资薪酬 | `web/src/pages/payroll-guidance.ts:26` |
| 通用凭证模板「工资计提」 | **`6601` 职工薪酬（成本）** | `vouchers/templates.ts:94` |
| 业务事项 `type=payroll` 的凭证草稿 | **`6601` 职工薪酬（成本）** | `events/routes.ts:656` |

**同一件业务事实，科目取决于用户从哪个入口进来。** 而工资模块——那个真正
处理工资、社保、个税、代发的模块——从头到尾没有碰过 `6601`。

`social-security-vouchers.ts:36-38` 的注释还专门记过一次同类事故：
「此前 expense 用表外科目 6602、payable 用非叶子的 2211，落账即污染报表口径」。
那次修的是社保链路，`6601` 这条支线没人动。

### 证据二：码、名、语义三者不一致

```ts
{ code: "6601", name: "职工薪酬（成本）", category: "expense", ... }
```

- 名字写「（成本）」，`category` 却是 `expense`；
- 系统里真正的成本类是 `4001` 生产成本 / `4101` 制造费用（`category: "cost"`）；
- 于是它在利润表里落进**期间费用**，不进营业成本——名字承诺的口径，代码不兑现。

### 证据三：它一直在制造事故，三处代码注释是疤

因为名字里有「（成本）」而编码又长得像国标的销售费用 `6601`，它被反复误用：

| 事故 | 现存注释 |
|---|---|
| 差旅费挂 `6601`，科目名却显示「销售费用-差旅费」 | `events/travel-expense-rules.ts:158`、`vouchers/account-code-guard.test.ts:265` |
| 采购报销把 `6601` 当销售费用 | `events/purchase-expense-rules.ts:158` |
| 预算差异「实际发生额」按 `6601` 取销售费用，长期漏计真正的销售费用 | `analytics/routes.ts:25-26` |
| 老板问答 / 助手按 `6601` 取费用 | `boss-qa/routes.ts:107-108`、`assistant/routes.ts:225` |

四处独立的错账，同一个根因：**一个语义不明的科目，占着一个语义明确的编码。**

测试夹具里也能看到同样的混淆——`reversal.test.ts:62`、
`close-drafts.integration.test.ts:91` 都写着 `accountCode: "6601", accountName: "管理费用"`。
写测试的人把它当成「随便一个费用科目」，而这恰恰说明它没有自己的语义。

### 证据四：它没有余额，也从来没有过

种子库（`finance_taxation_v4_test`）实测：

| 位置 | `6601` 的行数 |
|---|---|
| `ledger_entries` | **0** |
| `voucher_lines` | **0** |
| `voucher_draft_lines` | **0** |
| `recurring_voucher_lines` / `bank_accounts` / `fixed_assets`（3 列） | **0** |
| `accounts` | 4（每家公司一行科目定义） |
| `account_templates` | 1（种子模板定义） |

历史上唯一一条挂 `6601` 的分录是 `015_startup_year1_simulation.sql` 的
`le-007-2 计提4月销售人员工资`——**它早在迁移 041 就被改到 `6201` 销售费用了**
（`041_fix_seed_account_codes.sql:64`）。也就是说，上一次有人认真判断
「这笔挂 6601 的钱到底是什么」时，答案是「销售费用」，而不是「职工薪酬」。

`accounts` 表没有任何外键指向它（实测 `information_schema`：零条 FK 引用 `accounts`），
删除不会级联。它是 `level 1` 叶子科目，没有子科目，`accounts.path`（ltree）
不会产生孤儿节点。

### 它是怎么来的

`git log -S` 追到最早一次提交 `573d73d`（Phase 1，2026-05-15），
科目表建表时它就在那里，与整份硬编码科目表一起进来的。没有任何设计文档、
注释或提交信息解释它的存在。**没有正当理由需要保留。**

## 二、判断：废弃，借方改挂 `660201` 管理费用-工资

### 为什么是 `660201` 而不是 `4001` 生产成本

这是本方案最容易做错的一个决定，也是唯一需要论证的一个。

「按受益对象拆」的教科书答案里，生产工人的工资进 `4001` 生产成本 / `4101` 制造费用。
**但在今天的 FT 里，往 `4001` 记一笔工资的结果是这笔钱永远不进利润表。**

蓝图 E4 记录的两半问题，只修好了一半：

- **资产负债表一半已修**（V12-A5）：`classifyBalanceSheetAccount` 把成本类归入
  资产-存货，理由正当（生产成本余额的会计含义就是在产品）。
- **利润表一半没修**：`classifyProfitAccount` 对 `category: "cost"` 返回 `other`
  （`reports/profit-accounts.ts:73-82`），`summarizeProfitTotals` 对 `other`
  既不计收入也不计费用；`ledger/closing.ts:57` 的结转损益同样跳过它。

而**全仓没有任何成本结转代码**（`4001/4101 → 6401` 主营业务成本）——
蓝图「明确不引入清单」已经把它排除，因为结转需要产量与在产品数据，
超出财税平台范畴。

所以今天把默认模板指向 `4001`，效果是：工资挂在资产负债表的存货里，
利润表上永远看不到，直到有人手工做成本结转——而系统不提供这个功能。
**那比现状更糟。** 现状至少还进期间费用。

`660201` 管理费用-工资 则是一个可用、口径正确、且系统里已经在用的科目：

1. 它是工资模块自己的选择（社保计提就挂在这里），改过去等于**消除双轨**；
2. 小微企业绝大多数工资本来就是管理与销售人员，管理费用是最合理的默认值；
3. 模板与事项草稿本来就是**要人复核的默认值**，不是终局判断——
   `events/routes.ts` 产出的是 `status: "review_required"` 的草稿。

**生产制造场景怎么办？** 等 E4 的利润表一半修好（成本结转做出来）之后，
再把「生产人员工资 → `4001`」作为一个可选归属加回来。在那之前，
让制造业客户手工改科目，好过给他们一个会静默吞掉金额的默认值。

### 顺带把 D3 做完

`6601` 腾空之后，`6201 销售费用 → 6601`（国标编码）就没有障碍了。
这是 D3 唯一未完成的一项，本方案一并做掉。

## 三、迁移方案

两个迁移，**顺序不可颠倒**，分成两个文件而不是一个：071 是语义变更（废弃科目），
072 是纯改名。若 072 需要回退，071 不应跟着回退。

### 071_retire_payroll_cost_account.sql

**第一步：改挂存量数据（若有）。**

`6601 → 660201`，同时把 `account_name` 一并改成「管理费用-工资」
（沿用 041 的做法：精确等值匹配，不用 like / 前缀）。覆盖全部 8 个存科目码的列：

`ledger_entries.account_code`、`voucher_lines.account_code`、
`voucher_draft_lines.account_code`、`recurring_voucher_lines.account_code`、
`bank_accounts.account_code`、`fixed_assets` 的 3 列。

> 列表来自 `code-standardization.ts` 的 `ACCOUNT_CODE_COLUMNS`（D3 用
> `information_schema` 实测扫出来的），直接复用，不要凭印象重列。

**为什么是自动改挂而不是遇到数据就 `raise exception`。** 种子库是 0 行，
但客户库里可能有会计手工挂上去的分录。让迁移失败会把部署卡在一份迁移自己
修不了的数据上；而自动改挂在这里是安全的，因为：

- `6601` 与 `660201` **同为 `category: "expense"`**，
  `summarizeProfitTotals` 的 `expense` 档不变 → **利润总额与净利润一分不动**，
  只有费用明细构成（管理费用 vs 其他）会变；
- 风险引擎的工资分录检测不会漏——`risk/engine.ts:359-362` 已经同时认
  `22110101` 与 `660201`，去掉 `6601` 分支后检测能力不降反升；
- 改挂行数用 `raise notice` 打出来，不静默。

**第二步：删除科目定义。**

```
delete from accounts          where code = '6601';
delete from account_templates where code = '6601';
```

删除前断言 `not exists (select 1 from accounts where parent_code = '6601')`
——当前无子科目，但断言比注释可靠。`accounts.path` 无需重建：`6601` 是
level 1 叶子，路径就是它自己，删行即删路径。

**第三步：零残留自检。** 扫全部 8 列 + `accounts` + `account_templates`，
发现 `6601` 就 `raise exception` 回滚。与 070 同一套写法。

### 072_sales_expense_standard_code.sql

`6201 → 6601`。此时 `6601` 已空，**不存在占用链，单阶段改写即可**
（070 那种两阶段临时值只在占用链存在时才需要）。

范围比 071 多三处，因为这次动的是一个真实在用的科目：

- 上述 8 个数据列；
- `accounts.code`、`accounts.parent_code`、**`accounts.path`（ltree 重建）**、
  `accounts.id`（含编码，`company_id || ':' || code`）；
- `account_templates.code`、`account_templates.parent_code`。

同样以零残留自检收尾。

## 四、代码改动

### 写入路径（2 处，必须与 071 同批）

| 文件 | 改成 |
|---|---|
| `vouchers/templates.ts:94` | `line(..., "660201", "管理费用-工资", value, "0.00")` |
| `events/routes.ts:656-657` | `accountCode: "660201"`, `accountName: "管理费用-工资"` |

模板的 `description`（`templates.ts:89`「借职工薪酬，贷应付职工薪酬」）
与 `accounting-agent.ts:41` 的 `reason`（「计提职工薪酬成本」）也要改，
否则 AI 给出的理由与实际分录对不上。

### 读口径（与 072 同批）

**`risk/engine.ts:362` 删掉 `entry.accountCode.startsWith("6601")`——这一条是硬性的。**

072 之后 `6601` 就是销售费用。留着这个分支，等于把**所有销售费用分录**
判定成「工资薪酬相关分录」，进而对任何有销售费用的事项报
`PAYROLL_WITHOUT_IIT_ITEM`（high 级）。**这正是 D3 要消灭的那一类前缀陷阱，
只不过换了个方向发作。** 漏删这一行比漏改任何一处写入路径都严重。

`analytics/routes.ts:33` 的 `EXPENSE_PREFIXES`：071 后删 `"6601"`，
072 后把 `"6201"` 改成 `"6601"`。两次都别忘了同步上面 23-26 行那段注释，
它现在写着「6601 也不是销售费用而是职工薪酬」——072 之后这句话就反了。

`chart-of-accounts.ts`：删第 141 行（`6601` 定义），第 127 行 `6201 → 6601`。

`code-standardization.ts`：`ACCOUNT_CODE_MAPPINGS` 加一项
`{ legacy: "6201", standard: "6601", name: "销售费用" }`。

> **`RETIRED_CODES` 会自动算对，别手工加 `6601`。** 判据是
> 「在 legacy 里且不在 standard 里」（`code-standardization.ts:149-151`）。
> 加了这项之后 `6201` 进 legacy 且不在 standard → 判为 retired ✓；
> `6601` 是某项的 standard → 不判为 retired ✓。
> D3 在这个判据上栽过两次（迁移自检误报 2 处、源码护栏误报 12 个文件），
> 而 `6601` 正是新一轮的「两头都在」的编码——**手工往 `RETIRED_CODES` 里
> 塞 `6601` 会让护栏把全部销售费用代码报成待改**。

纯注释、不影响行为，但会误导下一个人的三处：
`boss-qa/routes.ts:107-108`、`assistant/routes.ts:225`、
`events/purchase-expense-rules.ts:158`、`events/travel-expense-rules.ts:158-159`。

前端一处：`web/src/pages/reports/panels/BudgetVariancePanel.tsx:108`
的 placeholder「留空=默认费用类，如 6601,6602」——现在的示例正好是被废弃的科目。

### 测试

替换字面量即可的：`ledger/closing.test.ts`、`vouchers/reversal.test.ts`、
`ai-agents/close/close-drafts.integration.test.ts:91`、
`reports/summary.test.ts:210`、`tools/v4/close-period-db.integration.test.ts`。

（顺带一提，`reversal.test.ts` 与 `close-drafts.integration.test.ts` 里
`6601` 配的是 `accountName: "管理费用"`——改成 `660201` 之后码名才第一次对上。）

**不能只替换字面量的一处**：`reports/profit-accounts.test.ts:32-38`。

```ts
// 6602 未登记在科目主数据里（种子分录用了表外科目）。旧的硬编码费用前缀表
// 只有 6601，hasPrefix("6602") 全不匹配 → other → 被 summarizeProfitTotals 静默丢弃。
```

这条测试守的是**兜底规则**（6 开头且非收入 → 一律费用），它的叙事以
「`6601` 是那张旧前缀表里唯一的费用科目」为前提。废弃 `6601` 之后前提消失，
要重写注释与断言来表达同一条不变式，而不是把 `6601` 换成别的码了事。

### 护栏：现有的就够，不用新加

`account-code-guard.test.ts` 已有的三条断言会自动接住漏改：

- 「凭证行必须挂科目表里存在的码」——071 删掉 `6601` 后，漏改的生成器立刻红；
- 「凭证行的科目名必须与科目表一致」——072 之后若某处还写
  `"6601" / "职工薪酬（成本）"`，科目表说 `6601` 叫「销售费用」，断言红。

这两条覆盖了 `templateUsages` / `eventMappingUsages` 等 7 个生成器，
不需要为本次改动增加新护栏。

## 六、本次不做

- **成本结转（`4001/4101 → 6401`）**：蓝图「明确不引入清单」已排除，需要产量与

- **`4001` / `4101` 与国标撞号**（国标成本类是 `5001` / `5101`，
  `4001` / `4101` 在国标里是实收资本 / 盈余公积）：D3 第九节已记录，
  当前无按 `4` 前缀判定的代码，不构成缺陷。与本方案无依赖关系。
