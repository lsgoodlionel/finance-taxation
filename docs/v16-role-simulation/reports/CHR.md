# 董事长 / 创始人（v4_chairman）操作实验报告

> 实验时间：系统日期 2026-08-27，会计期间 2026-08
> 环境：API `http://127.0.0.1:33100`，前端 `http://127.0.0.1:55173`
> 我造的数据（全部带 `[CHR]` 前缀）：
> - 事项 `evt-1787822519506-d484646d`「买设备 / 大件资产 · [CHR]中科曙光」128,000 元（走界面「记一笔」）
> - 事项 `evt-1787822735608-67d8dadb`「[CHR]复现测试·办公室房租」50,000 元（走 API，用于复现重复凭证）
> - 4 份合同：`contract-...szut9w` / `...wx7153` / `...2ezyeb` / `...fy7hr4`（其中两份租赁合同内容重复，是我第一次脚本没读对返回体重复提交造成的，均为我自己的数据）
>
> 我**没有**做：reset/seed 数据库、锁定或解锁会计期间、任何结转、任何过账。

---

## 我是谁

我是这家四五十人科技公司的老板。我不看分录，也不打算学。我每天早上给财务这件事十分钟，
就想知道三件事：**这个月赚没赚钱、钱够不够发工资、有没有要我签字或者要出事的**。
我信数字，但我更信我能点进去看到底的数字——一个我点不开的「净利润」，对我等于没有。
我对术语零容忍：界面上一出现「借贷」「勾稽」「过账」，我第一反应是这页不是给我看的。

---

## 10 件事的结果

### 1. 登录后 10 秒内搞清楚「这个月赚钱了吗」

- **怎么做的**：登录 → 系统自动落到 `/home`（引导模式，董事长默认）。不用点任何东西。
  桌面 1440×900 下「本月赚了多少」在 y=713，首屏可见；手机 390×844 下在 y=1805，**要往下滚两屏**。
- **结果**：**部分成功——而且看到的是错的结论**。
  首页写：**「本月赚了多少 ¥0.00 / 收入减去所有成本费用后，真正剩下的钱」**。
  实际情况是这个月**一条已过账分录都没有**，正确答案是「不知道」，不是「零利润」。
  同一屏上另外两张卡是对的：「本月要交多少税 → 暂无数据」「现金还能撑多久 → 还看不出来」。
  三张卡里两张说没数据，一张斩钉截铁说赚了 0 元。

  证据（同一个接口的同一次响应，口径自相矛盾）：
  ```
  GET /v2/dashboard/chairman
  "cards":[{"key":"tax","value":"—","trend":"暂无数据"}, ...]      ← 空值用 "—"
  "profitOverview":{"revenue":"0","netProfit":"0","netMargin":"0.00%"}  ← 空值用 "0"
  ```
  前端 `pages/home/HomeKpiSection.tsx` 里判空写的是 `netProfitText !== null`，
  而后端永远给 `"0"` 不给 `null`，所以「暂无数据」这条分支**永远走不到**。

- **便捷性**：0 次点击、0 秒。这一条系统做得最好。
- **逻辑正确性**：**错**。把「无数据」显示成「利润 0 元」。驾驶舱同一件事就处理对了
  （「本期还没有已记入正式账本（过账）的收入与费用」），说明团队知道该怎么写，只是首页没接上。
- **业务合理性**：不合理。老板拿「本月赚了 0」去开会，和拿「账还没记完」去开会，是两回事。
- **功能完整性**：入口完整，口径不完整。

### 2. 看懂利润的构成——钱主要花在哪里了

- **怎么做的**：`/home` →「本月赚了多少」卡（1 次点击）→ 跳到 `/reports?task=chairman`；
  另走「董事长驾驶舱」看「利润与费用概览 / 本月费用构成」。
- **结果**：**做不了**。
  1. 点「本月赚了多少」落到 `/reports` 的「老板摘要」，页面说
     **「这期的经营摘要还没准备好 / 需要财务同事先保存一次报表快照」**，
     而它下面的三表默认停在 **2026-05**（详见第 7 件事）。等于问「这个月怎么回事」，答「五月的表在这儿，摘要没有」。
  2. 驾驶舱有「本月费用构成」饼图，但角标常年写着**「内部拆分为估算值」**。
     查下来不是数据不够，是**后端算了没往外发**：
     `apps/api/src/modules/dashboard/summary.ts:108,169` 计算并返回了 `expenseBreakdown`，
     但 HTTP 处理函数 `apps/api/src/modules/dashboard/routes.ts:141-145` 组装响应时**没带上这个字段**。
     实测 `GET /v2/dashboard/chairman` 的顶层键只有
     `['period','periodStartDate','periodEndDate','cards','queues','profitOverview','riskBoard','aiSummary','riskCount']`，
     没有 `expenseBreakdown`。前端 `pages/dashboard/expense-slices.ts:63` 拿不到就退回
     **固定比例估算（主营成本 65%、人工 20%、销售费用 40%、管理费用 35%）**。
     前端源码自己写着「编出来的比例比不显示更糟」——现在跑的正是那条编出来的路径。
- **便捷性**：1 次点击就到，路径没问题。
- **逻辑正确性**：饼图口径是编的；老板摘要是空的。
- **业务合理性**：老板问「钱花哪了」，唯一那张图是按固定比例拍的。不能用。
- **功能完整性**：后端能力做完了，最后一步（塞进响应体）没做。

### 3. 找出等着我审批的事情，并批掉一笔

- **怎么做的**：`/home` →「需要您处理的事」→ 我那笔 12.8 万的卡片 → 点**「批准」**（1 次点击）。
- **结果**：**成功**。
  ```
  POST /api/close/drafts/vou-map-evt-1787822519506-d484646d-purchase/approve → 200
  ```
  界面提示「已批准，财务复核后就会正式入账」，卡片消失，「还有 3 件」变「还有 2 件」。
  重复批准有防护：再调一次返回 `409 {"error":"草稿已批准，不可重复处理"}`。
- **但是**：
  1. 侧栏那个叫**「我的审批」**的页面，全程是空的——「没有待你处理的审批」。
     首页说有 3 件等我批，驾驶舱说「1 张凭证等您审批」，`/inbox` 顶部写「**0** 等您审批」，
     而同一页下面挂着「AI 草稿 **3** 项待批准」。四个地方四个数。
     根子是系统里有两套「审批」：工作流实例（`/api/approval/pending` → `{"items":[],"total":0}`）
     和 AI 凭证草稿（`/api/close/drafts`），前台没合并，老板要自己知道去哪找。
  2. 卡片上的状态词写的是**「借贷待校验」**。这是唯一要我拍板的地方，却用了我不懂的词。
  3. 12.8 万一键批准，**没有任何二次确认**。
- **便捷性**：批一笔 1 次点击，快。但「找到要批的东西」这件事被三个入口拆散了。
- **逻辑正确性**：批准动作本身正确、幂等有防护；**待办计数四处不一致**。
- **业务合理性**：老板批的是「这笔业务认不认」，符合直觉。但「借贷待校验」这种词不该出现在老板界面。
- **功能完整性**：能批完，但批完之后发生了第 3 类问题——见下。

### 3-附：批准一次，凭证变两张（我认为这是最严重的一条）

- **怎么做的**：批准后回查这笔业务的凭证。
- **结果**：**同一笔 12.8 万，凭证中心里出现两张，各 12.8 万，都没过账。**
  ```
  GET /api/vouchers?businessEventId=evt-1787822519506-d484646d
  close-voucher-vou-map-...-purchase   status=draft            借 1601 固定资产 128000 / 贷 2202 应付账款 128000
  voucher-evt-...-payment              status=review_required  借 1601 固定资产 128000 / 贷 2202 应付账款 128000
  ```
- **可稳定复现**（我用第二笔 `[CHR]复现测试·办公室房租` 5 万验证）：
  ```
  POST /api/events                        → evt-1787822735608-67d8dadb
  POST /api/events/{id}/analyze           → 凭证 1 张（voucher-...-payment, review_required, 50000）
  POST /api/close/drafts/vou-map-{id}-expense/approve → {"ok":true,"voucherId":"close-voucher-..."}
  GET  /api/vouchers?businessEventId={id} → 2 张，各 50000（close-voucher-... draft / voucher-...-payment review_required）
  ```
  对照组：库里其他事项（没走过老板批准）都是 1 张。
- **界面上也看得见**：凭证中心（专业模式）列表里同一条摘要出现两行——
  一行标 `PURCHASE`（草稿，「下一步：校验并审核」），一行标 `-PAYMENT`（待审核，「下一步：校验并审核」）。
  ⌘K 搜「中科曙光」也直接搜出「事项 ×1 + 凭证 ×2」。事项详情页更是明写「已生成记账单据（凭证） **2 张**」。
- **风险**：两张都在会计的待办队列里、都可继续推进。如果两张都过账，这家公司的固定资产和应付账款各多 12.8 万。
  （**我没有过账，所以「是否真会双重入账」未验证**——过账会改共享账本，且当前公司没有会计期间。）
- **严重度**：我按「阻断」记。老板界面上最主要的一个按钮，按一下就在账上多出一张等额凭证。

### 4. 查一笔大额支出的来龙去脉（从数字追到原始单据）

- **怎么做的**：试了三条路。
  1. `/home` 卡片上的**「看详情」** → 落到 `/inbox`（「我的一天」专业工作台），**不是**这笔的详情页。
  2. 驾驶舱的数字 → **点不动**。查了源码，`pages/dashboard/` 下的
     `ProfitSummaryCard.tsx`、`DashboardKpiCards.tsx`、`CashForecastCard.tsx` 里
     没有任何 `Link` / `navigate` / `onClick`。整个驾驶舱的数字都是死的。
  3. **⌘K 全局搜索「中科曙光」** → 一次搜出 3 条（事项 1 + 凭证 2）→ 点事项 → `/events?event=...`。**这条走通了。**
- **结果**：**部分成功——追得到，但走的是老板不会用的路。**
  走通之后那一屏是全系统最好的一屏，事项页的「这一笔事项办到哪了」把整条链画出来了：
  ```
  ✓ 业务发生 → ✓ 提交 AI 财税秘书 → ✓ AI 初判与资料校验 → ✓ 外购物品分支判断
  → ✓ 外购物品审批与任务分发（3 个任务）
  → ✓ 外购物品生成单据与凭证草稿（采购合同/订单、供应商发票、资产验收单）
  → ● 凭证与税务处理中（列出 2 张凭证）→ ○ 税务复核与申报留档 → ○ 归档与可追溯查询
  现在这步：凭证与税务处理中 / 由谁办：财务部 / 税务岗位
  ```
  还有「在单据中心看这一笔的全部单据 →」「在凭证中心看这一笔的全部凭证 →」两个直达链接。
- **但是**：
  1. 这页顶上挂着横幅「**这是财务专业页面 · 经营事项总线 … 看不懂是正常的**」。
     系统自己劝我别看这页，可这是唯一能追溯的地方。
  2. 三份单据里，「采购合同/订单」状态是 `ready`（已就绪），而我**从没上传过任何合同**：
     ```
     GET /api/documents?businessEventId=evt-1787822519506-d484646d
     doc-...-purchase_contract | purchase_contract | ready
     doc-...-supplier_invoice  | supplier_invoice  | draft
     doc-...-acceptance_record | acceptance_record | draft
     ```
     一份不存在的合同显示「已就绪」，对老板是误导。
- **便捷性**：⌘K → 打字 → 1 次点击，其实很快。但一个老板不会知道 ⌘K；他会点「看详情」，然后被扔到专业页。
- **逻辑正确性**：链路数据是对的（甚至把重复凭证如实显示成 2 张）；单据 `ready` 状态不对。
- **业务合理性**：从数字到原始单据的追溯设计是对的，符合国内「账、证、表、单」互查的要求。
- **功能完整性**：功能完整，**老板入口缺失**。

### 5. 看这个月有什么税务风险

- **怎么做的**：`/home`「有没有风险」卡 → `/risk`；另看 `/tax`；另看 `/inbox`。
- **结果**：**部分成功，而且老板视角是漏的**。
  - `/home` 说：**「有没有风险：一切正常」**。
  - 驾驶舱说：**「高风险事项 0」**。
  - `/risk` 说：0 条风险发现，「全部已关闭」，关闭率满分。
  - 但 `/inbox`（专业页）顶上有一条横幅：
    **「📅 2026-08 申报到期：还有 4 个税种没申报，最近的『增值税及附加』还有 19 天到期」**。
  - API 印证：
    ```
    GET /api/tax/deadlines
    vat / iit / si / housing_fund 四个税种，dueDate 全是 2026-09-15，daysLeft 19，filed:false
    urgentCount: 0
    ```
  - `/tax` 页面还有更硬的一条：**「纳税人口径未建立 / 当前没有有效纳税人身份，税率规则与申报批次不能稳定推进」**，
    以及「待复核事项 2」。这条也没有出现在老板的任何一屏上。
- **便捷性**：老板路径 2 次点击到 `/risk`，看到「一切正常」就走了——这才是真实行为。
- **逻辑正确性**：`/home` 的「有没有风险」只读 `riskCount`（= `risk_findings` 未关闭数），
  完全不看「未申报税种」「纳税人身份未建立」「未过账凭证」。
  四个税种没报、纳税人身份没建，界面对老板说「一切正常」。
- **业务合理性**：不合理。国内中小企业老板真正会踩的税务坑就是「到期忘了报」和「身份/税率没配对」，
  这两件系统都知道，就是没往老板那儿送。
- **功能完整性**：数据齐、专业页齐，**老板聚合层漏了**。`/tax` 页对老板的降噪横幅写得很好
  （「您通常只需要知道『要交多少、什么时候交完』」），但那两个数恰恰没出现在老板首页。

### 6. 看现金流状况，判断下个月发不发得出工资

- **怎么做的**：`/home`「现金还能撑多久」→ 驾驶舱「钱够不够用？」段；API 对照 `/api/forecast/cash`。
- **结果**：**做不了，而且系统给了一个危险的肯定答复**。
  驾驶舱同一张卡上，上下两行互相打架（原文照抄）：
  ```
  钱够不够用？
  本期还没有账务数据，算不出可动用资金。      ← 上面这句是对的

  资金前瞻（2026-08）
  可动用资金 ¥0.00 / 结清后预计余额 ¥0.00 / 预计流入(应收) ¥0.00 / 预计流出(应付/税/薪) ¥0.00
  本期工资社保可发
  资金充裕：本期工资社保可发，结清全部应付与税负后预计仍余 ¥0.00。   ← 下面这句是危险的
  ```
  API 证据：
  ```
  GET /api/forecast/cash
  input:    cashBalance 0, receivables 0, payables 0, taxLiability 0, upcomingPayroll 0, upcomingSocialSecurity 0
  forecast: canPaySalary true, gap 0, verdict "资金充裕：本期工资社保可发，结清全部应付与税负后预计仍余 ¥0.00。"
  ```
  账上 0 元、工资需求 0 元，`0 >= 0` 判成「资金充裕、工资发得出」。
- **便捷性**：2 次点击能看到，找得到。
- **逻辑正确性**：**错**。「数据为 0」和「余额为 0 但够用」被算成同一件事。
  而且首页说「还看不出来」、驾驶舱说「资金充裕」——**两个老板页面对同一个问题给了相反的答案**。
- **业务合理性**：这是最不能出错的一句话。老板看到「资金充裕：本期工资社保可发」是会据此做决策的。
- **功能完整性**：预测模型有、口径有、界面有，缺的是「无数据时不给结论」这一道闸。

### 7. 查一份财务报表，并判断它是不是最新的

- **怎么做的**：`/home` →「看报告」（1 次点击）→ `/reports?task=chairman` → 切「看报表 → 资产负债表」。
- **结果**：**部分成功，且「是不是最新」这个判断被界面误导了**。
  - 页面状态条写：**「已更新 2026-05 财务三表。」** ——读起来像「刚刚更新过」，实际意思是「你正在看五月」。
  - 表头写：**「资产负债表　期末：2026-05-31」**。**今天是 2026-08-27。**
  - 原因是硬编码：`apps/web/src/pages/reports/ReportsShellContainer.tsx:47-49`
    ```ts
    const [year,  setYear]  = useState(2026);
    const [month, setMonth] = useState(5);
    const [quarter, setQuarter] = useState(2);
    ```
    页面**不读顶栏那个全局「会计期间」选择器**（全页只有「部门费用」子面板 `panels/CostCenterPanel.tsx:24`
    调了 `usePeriod()`）。所以**同一页上，资产负债表是 2026-05、部门费用是 2026-08**。
    而 `lib/period-context.tsx` 的注释白纸黑字写着「所有期间相关页面（工资/总账/**报表**/代发/导出/税务）默认读取此处选定的期间」。
  - 数据本身：`GET /api/reports/balance-sheet?period=2026-08` 全 0，`selfCheck.balanced: true`。
    一张全 0 的资产负债表被判定为「平衡」。
  - `GET /api/reports/snapshots` → `{"items":[],"total":0}`，所以「老板摘要」永远是「还没准备好」。
- **便捷性**：1 次点击到，很好。
- **逻辑正确性**：默认期间错、状态文案有歧义、页内两个期间并存。
- **业务合理性**：会计每月要出表，报表页默认应该是「上一个已结账期间」或「当前期间」，不该是写死的五月。
- **功能完整性**：报表都在（试算平衡/资产负债表/利润表/现金流量表/部门费用），
  但缺一个老板最想要的东西：**「数据截至 X 时间 / 已过账 N 张凭证 / 未过账 M 张」的新鲜度标注**。

### 8. 用「老板问答」或类似功能问一个业务问题

- **怎么做的**：先访问 `/boss-qa`，被重定向到 `/assistant`；在「决策视角」下问
  「这个月赚钱了吗？钱主要花在哪里了？」。
- **结果**：**部分成功——问答框能用，但真正的「老板专线」前台点不到，而且 AI 是桩回复。**
  1. 界面回答（`POST /api/assistant/chat → 200`）：
     > 「测试环境老板视角回复：已收到问题『这个月赚钱了吗？钱主要花在哪里了？』。
     > 当前建议先查看现金、税务与待办三项指标，再决定是否下钻到具体事项。」
     ——一个字的实际数据都没有。（测试环境桩，**真实 AI 回答质量未验证**。）
  2. 后端另有一个**专门给老板做的**接口 `POST /api/boss-qa/chat`
     （`apps/api/src/modules/boss-qa/routes.ts`），system prompt 里直接拼了一张财务快照表
     （可动用资金 / 待回款 / 本月税负 / 本月收入 / 本月支出 / 本月利润估算 / 高风险事项数 / 待处理任务数 + 近 10 条经营事项），
     还规定「数字优先、加粗关键数字、末尾附 1-3 条可执行建议、50-400 字」。**这正是我要的东西。**
     但是：
     - 前端全仓库对 `/api/boss-qa` **零引用**（`grep -rn "api/boss-qa" apps/web/src` 无结果）；
     - `/boss-qa` 这个路由在 `App.tsx:120` 被 `<Navigate>` 重定向到 `/assistant`（`lib/entry-guidance.ts:25`）；
     - `/assistant` 走的是另一个端点。**这个能力等于不存在。**
     - 直接调它还会报 AI 配置错：
       ```
       POST /api/boss-qa/chat {"messages":[{"role":"user","content":"这个月赚钱了吗？..."}]}
       data: {"type":"error","error":"http://host.docker.internal:11434/... HTTP 404 {\"error\":{\"message\":\"model 'gemma4:latest' not found\"}}"}
       ```
  3. **「前台入口护栏」对它是绿的。** 我跑了
     `npx tsx --test apps/api/src/routes/registry-frontend-coverage.test.ts` → 2 passed，
     已知缺口清单 8 条里**没有** `/api/boss-qa/chat`。
     原因是那条护栏在找不到字面前缀时会退到「末段」匹配，`/api/boss-qa/chat` 的末段是 `chat`，
     而前端有 `/api/assistant/chat` ——**被别的路由顶包了**，正是护栏注释里自己写的「最坏的失效方式：绿的，但什么都没在看」。
- **便捷性**：顶栏就有「问 AI」，1 次点击，入口最好找。
- **逻辑正确性**：桩回复不携带任何真实数据；老板专线拿不到。
- **业务合理性**：设计意图完全对路（老板要结论不要报表）。
- **功能完整性**：**后端做完了，前台点不到——本项目反复出现的那类缺陷，这次在最该给老板用的功能上又出现了一次。**

### 9. 看看有哪些合同快到期了

- **怎么做的**：我先建了 3 份 `[CHR]` 合同（已到期 / 14 天后到期 / 明年到期），
  然后从「合同与往来」的**列表**和**看板**两个视图找。
- **结果**：**做不了**。
  - **列表视图根本没有「到期日期」这一列**：表头是「合同标题 / 类型 / 交易方 / 金额 / 状态 / 关联事项 / 操作」。
  - 筛选器只有「合同类型」和「合同状态」，**没有「即将到期」筛选，也不能按到期日排序**。
  - 「合同状态」里有个「已到期」选项，但**没用**：我那份 2026-08-20 就已经过期的
    `[CHR]年度云服务采购` 状态仍然是「执行中」——系统不会按 `endDate` 自动置为已到期。
  - 只有**看板**卡片上有到期日文字。代码里 `pages/contracts/ContractKanbanCard.tsx:36-38`
    确实算了 `isExpiringSoon`（30 天内），但表现形式只是把那行小字从灰色变成橙色——
    没有徽标、没有排序、没有汇总。而且判据是 `endDate - now < 30 天`，
    **已经过期的（负数）和还有 14 天的一视同仁**，橙色一样。
  - 首页 `/home` 和董事长驾驶舱**完全没有合同相关的任何提示**。
  - 顺带：看板卡片上采购合同的类型显示成英文原文 `purchase`，租赁/销售却是中文。
- **便捷性**：2 次点击到合同页，然后卡住——没有任何一个视图能回答「哪些快到期」。
- **逻辑正确性**：到期状态不自动流转；「快到期」与「已过期」不区分。
- **业务合理性**：不合理。房租、云服务、框架协议到期忘续是中小企业最常见的经营损失之一，

- **功能完整性**：**缺一个「即将到期合同」清单 + 首页提醒**。数据都在（`endDate` 字段完整），差的是聚合与推送。

### 10. 找一下系统的操作指南，看看作为老板我该关注什么

- **怎么做的**：`/home` 右上角「本页指南」（1 次点击）；再进「系统中心 → 关于系统 → 在线预览完整说明书」。
- **结果**：**成功，而且是这次实验里质量最高的一块。**
  - 「本页指南」抽屉写得对老板：
    > 适用：所有人，尤其是不看账的管理者 …
    > **数字只统计已过账的凭证，月中看到的会偏低——月末结完账才是完整的**
    > 上下游：汇总自各业务模块，这一页不录任何东西
  - 完整说明书信息量很大也很实在：管理员上手 8 步、角色权限表、日常节奏表（每天/每周/每月末/每年末谁做什么）、
    数据流动（报销 / 合同付款 / 生产成本 / 增值税 / 月结年结）、40 个页面逐页说明、38 条术语表。
  - 里面直接回答了「为什么我的账上什么都没有」：
    > **8. 总账中心 → 录入期初余额。这是最关键的一步。**…不做的话银行存款从零开始、资产负债表不平、所有报表都是错的。
  - 也明确写了对我这个角色的约束：
    > 董事长 / 创始人：全部功能，含系统配置。**但仍受职责分离约束：自己复核过的凭证不能自己再过账**
- **但是——手册和界面对不上，而手册自己承诺了不会对不上**：
  「关于系统」页写着「说明书由系统实时生成…与每页右上角的『本页指南』**读的是同一份数据，不会出现手册说一套、界面做另一套**」。实际：
  1. 手册讲 `/home`：「看顶部**三张**卡：**本期利润、可用资金、待办件数**」。
     实际首页是**四张**卡，叫「现金还能撑多久 / 本月赚了多少 / 本月要交多少税 / 有没有风险」，
     而且「待办」是卡片**上方**的独立区块，不是卡片。
  2. 手册讲 `/quick-entry`：「适用角色：**会计**」「怎么用：选支出类型（房租、水电、差旅……）→ 填金额与日期 →
     **确认系统给出的科目，不对可以改**」。
     实际那是个 3 步白话向导（拍照/打字 → 确认 → 完成），**通篇没有「科目」两个字**，
     而且它就摆在老板首页的快捷入口上（「记一笔 / 花了钱、收了钱，说一句就行」）。
- **便捷性**：1 次点击，每页都有，位置一致。很好。
- **逻辑正确性**：结构与承诺一致，**内容有陈旧**。
- **业务合理性**：对老板讲「你该关注什么」讲得清楚，角色分工和月度节奏是符合国内实务的。
- **功能完整性**：完整（还能存 PDF）。只需要把逐页说明和真实界面对一遍。

  「您通常只需要知道『要交多少、什么时候交完』」，并给「回今天」按钮。这个设计非常对。
- **本页指南 + 完整说明书**：每页 1 次点击，内容实在（含「数字只统计已过账的凭证，月中看到的会偏低」这种关键限制）。
- **重复批准有防护**：第二次 `approve` 返回 `409 草稿已批准，不可重复处理`。
- **驾驶舱的留白很诚实**：「这 6 个期间账上都还没有一笔账的借贷明细（分录）」「本期还没有已记入正式账本（过账）的收入与费用」——
  这套口径要是搬到首页和资金卡上，第 2、3 条问题就不存在了。

---

## 一句话总结

**现在还不能用。** 这套系统给老板准备的东西其实很齐——首页白话卡、驾驶舱、事项时间轴、全局搜索、本页指南、
甚至一个专门写给老板的 AI 问答 prompt——但**我最想知道的三件事，它给了我三个错误答案**：
「本月赚了 ¥0.00」（其实是没数据）、「资金充裕，工资发得出」（其实账上一分钱都没有）、「一切正常」（其实四个税种没申报、纳税人身份都没建）。
再加上我点一次「批准」就让一笔业务变成两张等额凭证——**老板界面上唯一那个动作按钮，会把账搞坏**。

缺的不是功能，是**三条纪律**：
1. **没数据就说没数据**，不许拿 0 当结论（第 2、3 条问题）；
2. **一个问题只能有一个答案**，首页、驾驶舱、我的一天、我的审批不能各说各的（第 6、8、9 条）；
3. **后端做完不等于做完**——老板专线、费用构成明细、合同到期，都是后端有、前台点不到（第 4、7、13 条），
   而唯一该拦住这类问题的护栏，这次自己是绿的（第 5 条）。
