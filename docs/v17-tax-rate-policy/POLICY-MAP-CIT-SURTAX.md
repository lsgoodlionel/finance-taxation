# 企业所得税优惠与附加税政策映射表（V17 阶段三）

> 这份文件先于代码，理由同[增值税那份](POLICY-MAP.md)：**直接改代码会变成猜政策**。
>
> 阶段三比阶段一政策面大得多——增值税只要回答「这笔业务用哪一档」，
> 企业所得税要回答「这家企业够不够格享受优惠」，而资格判定依赖
> 一整套企业属性；附加税则依赖**实际缴纳**的主税，是跨模块的联动。

---

## 1. 现状

### 1.1 企业所得税：写死 25%

`modules/tax/corporate-income-tax.ts`：

```ts
const incomeTaxRate = 25;
const prepaymentTaxEstimate = taxableIncomeEstimate * incomeTaxRate * 0.01;
```

没有优惠税率、没有弥补以前年度亏损、没有已预缴抵减。

还有一处更隐蔽的：

```ts
const accountingProfit = Math.max(parseAmount(...totalProfit), 0);
```

**亏损被抹成 0。** 对当期预缴而言「亏损不缴税」的结果是对的，
但亏损本身是要**结转以后年度弥补**的资产，抹平之后这个信息就没了。

### 1.2 附加税：只筛不算

`modules/tax/stamp-surtax.ts` 全文 21 行，做的事是把税种名含「附加」的
税项**筛出来展示**：

```ts
const surtaxItems = scoped.filter((item) => item.taxType.includes("附加"));
```

一分钱都不算。这些税项要靠人手工建——没人建，页面就永远是空的。
科目（222106 应交税费-城建税及附加）、凭证模板、种子里一条写着
「城建税7%+教育附加3%+地方教育附加2%=12%」的说明都有，
**唯独没有计算**。

## 2. 政策依据

### 2.1 企业所得税税率

| 情形 | 税率 | 依据 |
|------|------|------|
| 一般企业 | 25% | 企业所得税法第四条 |
| 高新技术企业 | 15% | 企业所得税法第二十八条第二款 |
| 小型微利企业 | **实际 5%** | 见 2.2 |

### 2.2 小型微利企业优惠的算法

现行政策（财政部 税务总局公告 2023 年第 12 号等，执行至 2027-12-31）：

> 年应纳税所得额不超过 300 万元的部分，**减按 25% 计入应纳税所得额**，
> 按 **20%** 的税率缴纳企业所得税。

即：`应纳税额 = 应纳税所得额 × 25% × 20%`，实际税负 **5%**。

**这不是「税率 5%」。** 写成 `rate = 5` 在数值上一样，但一旦政策调整
（历史上这两个系数分别调过），或者需要在申报表上分别列示
「减免税额」，写死 5% 就还原不出来。**两个系数要分开存。**

小型微利的认定条件（同时满足，缺一不可）：

| 条件 | 阈值 |
|------|------|
| 行业 | 从事国家非限制和禁止行业 |
| 年度应纳税所得额 | ≤ 300 万元 |
| 从业人数 | ≤ 300 人 |
| 资产总额 | ≤ 5000 万元 |

### 2.3 弥补以前年度亏损

| 情形 | 结转年限 | 依据 |
|------|----------|------|
| 一般企业 | 5 年 | 企业所得税法第十八条 |
| 高新技术企业、科技型中小企业 | 10 年 | 财税〔2018〕76 号 |

顺序：**先亏先补**。弥补后的余额才是应纳税所得额。

### 2.4 已预缴税额抵减

汇算清缴：`应补(退)税额 = 应纳税额 - 已预缴税额`。
结果为负是**应退**，不是 0——把它截断成 0 等于让企业白交。

### 2.5 附加税

| 税费 | 税率 | 依据 |
|------|------|------|
| 城市维护建设税 | 市区 **7%** / 县城、镇 **5%** / 其他 **1%** | 城市维护建设税法（2021-09-01 施行） |
| 教育费附加 | **3%** | 征收教育费附加的暂行规定 |
| 地方教育附加 | **2%** | 财综〔2010〕98 号 |

**计税依据是「实际缴纳」的增值税、消费税**，不是「应纳」——
当期有留抵、有减免、分期缴纳时两者不等。

**六税两费减半**（财政部 税务总局公告 2023 年第 12 号，执行至 2027-12-31）：
增值税小规模纳税人、小型微利企业和个体工商户，上述三项**减征 50%**。

## 3. 判定所需的信息：又一次不在系统里

和阶段一同一个结论——缺的不是公式，是**判定所需的信息本身**。

| 判定 | 需要的信息 | 现状 |
|------|-----------|------|
| 小型微利 | 从业人数、资产总额、行业是否受限 | **`companies` 表全都没有** |
| 高新技术企业 | 资质编号与有效期 | **没有** |
| 城建税档位 | 纳税人所在地是市区 / 县镇 / 其他 | **没有**（只有 `registered_address` 自由文本） |
| 弥补亏损 | 以前年度亏损台账（金额、年度、已弥补额） | **没有这张表** |
| 已预缴抵减 | 本年度已预缴税额 | **没有**（申报批次表只有 tax_type / period / status，不存金额） |
| 附加税计税依据 | **实际缴纳**的增值税 | 有应纳税额，但没有「实际缴纳」这个事实 |

最后一行值得单独说：附加税依附于实缴主税，而系统里
「这笔增值税实际交了多少、什么时候交的」这个事实**没有落点**。
没有它，附加税只能按应纳额估算——那是个近似值，不能直接拿去申报。

---

## 4. 判定优先级与「不猜」原则

沿用阶段一的口径：**信息不足时不给数字，报「待确认」**。

企业所得税税率的判定顺序：

```
1. 高新技术企业（资质在有效期内）         → 15%
2. 小型微利（四个条件同时满足）           → 应纳税所得额 × 25% × 20%
3. 一般企业                              → 25%
4. 资格信息缺失                          → **不按 25% 兜底，报「优惠资格待确认」**
```

第 4 条与增值税那边的「税目待确认」是同一件事，但方向相反，值得说清：

- 增值税不知道税目 → 按 13% 兜底会**多收税**
- 企业所得税不知道资格 → 按 25% 兜底也会**多收税**

两者都是「按最高档兜底」，看起来「保守稳妥」，实际上都是**让企业多交钱**，
而且是静默的——用户看不出这个数字是猜的。所以两边一样：**说不出就说说不出。**

附加税同理：主税实缴额未知时不估算，报「待主税缴纳后计算」。

## 5. 分批落地

阶段三的面太大，一次做完会变成一个几千行、无法逐条验证的改动。分三批：

### 批次 A（已完成，见第 7 节）：把税率判定与优惠算法做对

1. 新增 `companies` 的税收资格字段：从业人数、资产总额、高新资质及有效期、
   城建税所在地档位
2. 新增 `corporate-income-tax-rate.ts`：优惠资格判定 + 两系数算法
3. **资格信息缺失时不按 25% 兜底**，报「优惠资格待确认」
4. 亏损不再抹成 0——负的应纳税所得额如实带出，供后续弥补

### 批次 B（已完成，见第 8 节）：附加税真的算出来

1. 城建税 / 教育费附加 / 地方教育附加的计算模块
2. 计税依据取**实缴**增值税；实缴额未知时报「待主税缴纳后计算」
3. 六税两费减半的判定（小规模 / 小型微利）

### 批次 C：弥补亏损与已预缴抵减

1. 亏损台账表（年度、金额、已弥补、结转期限）
2. 预缴记录
3. 汇算清缴：应补退税额可以为负（应退）

## 6. 这次不做什么

- **不做行业限制清单判定**：「国家非限制和禁止行业」对应的是一份产业目录，
  逐条落进系统是独立工程。本次由用户自行声明，字段上标明这是**声明值**
  而不是系统判定值
- **不做资质自动核验**：高新资质有效期由用户录入，不对接外部核验
- **不碰消费税**：附加税的计税依据里还有消费税，但系统里没有消费税模块，
  这次只按增值税算，并在结果里说明这一点

## 7. 批次 A 的实现记录

### 7.1 改了什么

| 层 | 改动 |
|----|------|
| 迁移 102 | `companies` 加从业人数、资产总额、限制行业声明、高新资质有效期、城建税所在地档位。**全部可空**——`null`（没登记）与 `0`（确实是 0）语义不同 |
| 判定 | 新增 `corporate-income-tax-rate.ts`：四级优先级，两系数算法，资格缺失返回 null |
| 汇算 | `buildCorporateIncomeTaxPreparation` 接上判定；契约加 `preferenceKind`、`preferenceNotice`、两个系数、`carryforwardLoss` |
| 录入 | 公司设置页加「税收资格」区；后端归一化单独成模块 |

### 7.2 三个容易写错的地方

**一、空串不能变成 0。** 表单清空输入框传上来是空串，`Number("")` 得到 **0**——
一家没登记的公司就变成「0 人 0 资产」，恰好落在小微阈值内，按 5% 算税。
少交的税要补，还有滞纳金。归一化单独成模块就是为了这一条能单独测。

**二、元与分的换算只能有一处。** 界面按元、库里按分。第一版我在
`CompanyTab` 和 `TaxQualificationSection` 两处都写了换算，结果输入的元值
被原样当作分传出——**测试当场抓住**：输入 200 万，传出 2000000 分（2 万元），
每保存一次缩小 100 倍。换算收进组件内部一处做完。

**三、亏损不能抹成 0。** 原代码 `Math.max(totalProfit, 0)`：当期不缴税
这个结论没错，但「可结转多少亏损到以后年度」这个信息一起没了。亏损是资产。

### 7.3 既有测试的处理

两条既有测试断言 `incomeTaxRate === "25"`。它们验的是**取数口径**
（会计利润取税前利润总额而非净利润），不是税率——给它们一个明确走
一般税率的资格（从业人数 500），**原有断言一条没改**。

### 7.4 集成测试用了另一家公司

`cmp-v4-tech` 一张凭证都没有，利润恒为 0，走不到税率判定那一段。
集成测试改用 `cmp-tech-001`——**只有它有真实的已过账分录**。

## 8. 批次 B 的实现记录

### 8.1 先补的是一个「事实」，不是一个公式

附加税以**实际缴纳**的增值税为计税依据。这个事实此前在系统里**没有落点**：
申报批次的状态机是 `draft → review_required → ready → submitted → archived`，
到 submitted 就结束了，**不含「已缴纳」，也不存金额**。

所以批次 B 的第一步不是写计算，是新增 `tax_payments` 表把这个事实记下来。
没有它，附加税只能按应纳额估算——而应纳与实缴在有留抵、有减免、
分期缴纳时都不相等，用户会拿这个近似值去申报。

| 层 | 改动 |
|----|------|
| 迁移 103 | 新增 `tax_payments`：税种、属期、实缴金额（分）、缴款日、可空的凭证关联 |
| 计算 | 新增 `surtax.ts`：三档城建税 + 教育费附加 3% + 地方教育附加 2%，六税两费减半 |
| 汇总 | `stamp-surtax.ts` 从「只筛不算」改为接上计算结果 |
| 录入 | `POST/GET /api/tax/payments`；界面上缴款登记放在附加税那一块 |

### 8.2 三条不能省的判断

**一、实缴未知时不估算。** 报「待主税缴纳后计算」。与增值税「税目待确认」、
企业所得税「资格待确认」同一口径：申报表上的数字必须是准的。

**二、所在地档位未登记时不默认按市区 7%。** 那会让县城企业多交 2 个点，
与「按最高档兜底」是同一个错误。

**三、`0` 与 `null` 不同。** 当期确实没缴增值税（比如全部留抵），
附加税就是 0，这是个确定的结论，不该让用户去等什么；
而「没有缴款记录」是不知道，要等。

### 8.3 反向验证抓到的两处

集成测试把实现改坏后各自变红：

- **不合计多笔**（`sum` 改成 `max`）：分期缴纳时会算少
- **不按税种过滤**：企业所得税的缴款混进增值税的计税依据，算多好几倍

### 8.4 界面上两个此前会出错的显示

**一、`税率：{incomeTaxRate}%`。** 批次 A 之后这个值可能是 `null`，
会渲染成「税率：%」——一个看不懂的空白。改成显示「待确认」加缺什么。

**二、附加税那块只有「事项数：0」。** 那个数永远是 0（没人手工建税项），
现在显示算出来的三项金额与合计。

### 8.5 六税两费减半的判定复用已有的两处

小规模看纳税人档案，小微复用 `corporate-income-tax-rate.ts` 的判定——
**小微的四个条件不在这里再写一遍**，写第二遍迟早漂移。

## 9. 验收标准

1. 一家高新技术企业按 **15%** 算，不是 25%
2. 一家小型微利企业（四条件齐备）按 **5%** 实际税负算，且能分别列出
   「减计的应纳税所得额」与「适用税率 20%」两个系数
3. 应纳税所得额超过 300 万时**不再是小型微利**，按 25%
4. 从业人数或资产总额缺失时，**不按 25% 兜底**，报「优惠资格待确认」
5. 亏损年度的应纳税所得额是负数，不是 0

### 批次 B

6. 登记一笔实缴增值税后，附加税按所在地档位算出三项金额与合计
7. 分期缴纳的多笔要**合计**，别的税种的缴款**不进**计税依据
8. 没有缴款记录时报「待主税缴纳后计算」，**不按应纳额估算**
9. 所在地档位未登记时不默认按市区 7%
